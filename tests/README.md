# Проверки кабинета

## Быстрые проверки без доступа к рабочей базе

Нужны Python 3.12+ и Node 24.

```sh
npm ci
npx playwright install --with-deps --only-shell chromium
npm test
```

`npm test` проверяет извлечение всех домашних заданий ЕГЭ, сохранение математической
записи, актуальность сгенерированного файла и работу журнала в Chromium: выбор
каждой из 20 лекций, сохранение индивидуального текста, отправку и просмотр учеником.
Браузерные тесты используют только локальные тестовые аккаунты и имитацию Supabase.
Они также проверяют открытие своего повторения и запрет доступа к чужому.
GitHub Actions запускает эти проверки на push и pull request.

Проверки доски также входят в `npm test`: 12 сценариев контроллера в Node и 10 сценариев
страницы доски в Chromium. Описание механизма и границ восстановления — в
[`docs/board-persistence.md`](../docs/board-persistence.md).

После изменения ДЗ в `el1.html`–`el20.html`:

```sh
python3 scripts/build_homework.py
npm test
```

Сгенерированный `assets/homework-ege.js` содержит только ученические условия.
Условия редактируются в уроках; в сгенерированном файле их не редактируют.

## Проверка настоящих правил доступа

`student-access.sql` запускается владельцем базы в SQL Editor или через
`psql -v ON_ERROR_STOP=1 -f tests/student-access.sql` в отдельном тестовом подключении.
Скрипт проверяет 17 условий для двух учеников, непривязанного аккаунта, учителя и гостя.
Все фиктивные пользователи, повторения и метаданные файлов откатываются: при успехе
через внутреннюю транзакцию, при ошибке — вместе со всем SQL-оператором.
Настоящие файлы не загружаются и не удаляются.

Эта проверка не запускается GitHub Actions в рабочей базе. Для автоматизации SQL
в CI нужен отдельный тестовый Supabase или локальный стек с исходной схемой.

`board-persistence.sql` запускается тем же способом: 20 проверок атомарных действий,
повторов, прав доступа и совместимости со старой версией. Фиктивные записи откатываются.

## Исторический набор

`e2e.js`, `db-check.sql`, `test-plan.md`, `bugs.md` и `results.json` относятся к прежним
версиям. Старый e2e требует закрытого ключа учительских материалов и ключей ответов;
его результаты нельзя считать результатами текущего `npm test`.
В старом наборе остаются ожидания учебниковых ДЗ; до обновления всего набора он
не является обязательной проверкой публикации. Закрытые ключи в репозитории не хранятся.

## Посещения и записи без текста ДЗ

Браузерный набор также проверяет занятия без текста ДЗ (включая запись только с файлом), обновление посещений через 30 секунд без потери несохранённого текста, ошибки чтения и восстановление после подключения к сети. Ошибки RPC не раскрывают ответ сервера.

`visits.sql` отдельно проверяет настоящий `edu_ping` и доступ к посещениям. Все вымышленные записи откатываются внутри SQL-оператора; данные учеников не изменяются.

## Итог урока

`lesson-summary-browser.js` проверяет подготовку итога из журнала, приватный черновик, выделение реального фрагмента доски, предварительный просмотр, отправку, список ученика, изоляцию последующих правок, отказ сохранения и отзыв доступа. Проверяется мобильная ширина 390 px.
`lesson-summary.sql` проверяет 13 условий доступа и валидации с полным откатом вымышленных данных.
Для отдельной браузерной проверки: `BROWSER_TESTS=lesson-summary-browser.js node tests/run-browser-checks.js`.

## Общие учебные каталоги

`catalogs.test.js` проверяет ссылки на тесты, темы, подсказки ДЗ и независимость локальных копий.
`catalogs-browser.js` проверяет общий каталог на главной странице (оба блока), в домашке, журнале и успеваемости.
После редактирования `assets/catalogs.js` запустите `python3 scripts/version_catalogs.py`, затем `npm test`.
Подробности — [docs/catalogs.md](../docs/catalogs.md).

## Новые уроки по четырём учебникам

`test_lesson_pack.py` проверяет комплектность четырёх уроков, отсутствие ключей в
публичных тестах, изображения слайдов и наличие зашифрованных материалов учителя.
`lesson-pack-browser.js` проверяет ученика, сдачу листа, восемь самопроверок,
назначение полного ДЗ из журнала и запрет входа ученика в раздел учителя.
С `LESSON_PRIVATE_INPUT` дополнительно проверяются реальные зашифрованные
конспекты, листы и четыре оглавления учителя. Приватные ключи CI не нужны.
Состав и повторная сборка — [docs/lessons-2026-11-18.md](../docs/lessons-2026-11-18.md).
